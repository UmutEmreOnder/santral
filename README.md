# Santral

Point any OpenAI-compatible app at your local CLI agents (Claude Code, Codex, Gemini CLI, ...).

## How it works

Santral serves an OpenAI-compatible `/v1/chat/completions` endpoint on `127.0.0.1:8765`. The request's `model` field picks which CLI agent handles the prompt (`claude`, `codex`, `gemini`, or any custom agent you've configured). If the agent answers within `sync_wait` seconds (25 by default), the HTTP response carries the answer directly. If it's still running past that point, Santral replies immediately with an acknowledgement and keeps the agent running in the background; when it finishes, the result is delivered via `notify-send`. Follow-up requests sent within `session_window` seconds (300 by default) of the previous one resume the same CLI session instead of starting fresh, so multi-turn conversations keep their context.

## Requirements

- Python 3.11+ (uses `tomllib` from the standard library)
- Linux: desktop notifications use `notify-send`; if it isn't installed, background results are printed to stdout instead
- At least one agent CLI installed and on `PATH` (`claude`, `codex`, `gemini`, or your own)

## Quickstart

```bash
install -m 755 santral.py ~/.local/bin/
~/.local/bin/santral.py
```

Then send it a request:

```bash
curl localhost:8765/v1/chat/completions -d '{"model":"claude","messages":[{"role":"user","content":"hello"}]}'
```

## systemd

To run Santral as a user service:

```bash
mkdir -p ~/.config/systemd/user
cp santral.service ~/.config/systemd/user/
systemctl --user daemon-reload && systemctl --user enable --now santral
```

systemd user services don't inherit your login shell's `PATH`, so agent CLIs installed outside the default service path (e.g. `claude` in `~/.local/bin`) will fail with "CLI not found" even though they work in your terminal. Add a drop-in extending the path:

```bash
mkdir -p ~/.config/systemd/user/santral.service.d
printf '[Service]\nEnvironment=PATH=%%h/.local/bin:/usr/local/bin:/usr/bin:/bin\n' > ~/.config/systemd/user/santral.service.d/path.conf
systemctl --user daemon-reload && systemctl --user restart santral
```

## Configuration

Santral reads `~/.config/santral/config.toml` if it exists; every key is optional and falls back to a built-in default. Use `config.example.toml` in this repo as a starting point: copy it to `~/.config/santral/config.toml` and uncomment what you need. Agent definitions merge per-field over the three built-ins (`claude`, `codex`, `gemini`): any field you set overrides the built-in, everything else is inherited unchanged.

Top-level keys:

| Key | Default | Meaning |
| --- | --- | --- |
| `port` | `8765` | TCP port to listen on (bound to `127.0.0.1`) |
| `sync_wait` | `25` | Seconds to wait for an agent before answering with an ack and going async |
| `agent_timeout` | `600` | Hard subprocess timeout, in seconds |
| `default_agent` | `"claude"` | Agent used when the request's `model` field doesn't match a configured agent |
| `session_window` | `300` | Follow-ups within this many seconds resume the previous session; `0` disables session continuity |
| `prompt_prefix` | `""` | Prepended to the user text (separated by a blank line) before it's sent to the agent; empty disables it |

Per-agent fields (under `[agents.<name>]`):

| Field | Meaning |
| --- | --- |
| `command` | Argv template used to start a fresh session (required for any agent, built-in or custom) |
| `resume_command` | Argv template used to resume the last session; omit to make the agent always start fresh |
| `model` | Model name, substituted into `model_args` |
| `effort` | Reasoning-effort value, substituted into `effort_args` |
| `model_args` | Argv fragment appended when `model` is set, with `{model}` substituted in |
| `effort_args` | Argv fragment appended when `effort` is set, with `{effort}` substituted in |

Placeholders available in argv templates:

- `{prompt}`: the latest user message. If any argv element contains it, it's substituted directly and nothing is piped to stdin; otherwise the prompt is piped to the process's stdin.
- `{session_id}`: a per-agent UUID generated by Santral, substituted into `command`/`resume_command`.
- `{model}`: substituted inside `model_args` only.
- `{effort}`: substituted inside `effort_args` only.

## Built-in agents

| Agent | Fresh command | Resume command | Model | Effort |
| --- | --- | --- | --- | --- |
| `claude` | `claude -p --session-id {session_id}` | `claude -p --resume {session_id}` | `--model {model}` | `--effort {effort}` |
| `codex` | `codex exec -` (prompt on stdin) | `codex exec resume --last -` | `-m {model}` | `-c model_reasoning_effort={effort}` |
| `gemini` | `gemini -p {prompt}` | `gemini --resume latest -p {prompt}` | `-m {model}` | not supported |

## Example client: OpenWhispr

In OpenWhispr, set the dictation agent's self-hosted endpoint to `http://127.0.0.1:8765` and pick one of your configured agent names (e.g. `claude`, `codex`, `gemini`) in the model field. Requests dictated through OpenWhispr will be routed to that CLI agent exactly like the curl example above.

## Caveats

- Only the latest user message is forwarded to the agent; Santral does not resend prior conversation history. Multi-turn continuity relies entirely on the underlying CLI's own session resume.
- For `codex` and `gemini`, "resume" targets the CLI's *most recent* recorded session, not necessarily one Santral started; if you've used the same CLI manually in a terminal in the meantime, a follow-up request may resume that session instead.
- Session memory is kept in-process. Restarting Santral forgets which sessions are still "warm," so the next request for each agent starts a fresh session.
- There is no authentication. Santral binds to `127.0.0.1` only and is meant to be reached from the local machine.
